Hamasen 哈瑪星 for Linux: your servers and cloud drives as folders in the file manager, in a GTK 4 / libadwaita app with a system tray icon.

## Requirements

GTK 4, libadwaita 1.5 or later, GVfs and a desktop keyring. `rclone` and `fuse3` are needed for Google Drive, OneDrive, Dropbox and S3.

## What's in it

- **SFTP, FTP, SMB, WebDAV and NFS** are mounted through GVfs and appear in the file manager sidebar and in every GTK file chooser
- **Google Drive, OneDrive, Dropbox and Amazon S3-compatible storage** are mounted through rclone as folders under `~/Hamasen`, with a sidebar bookmark. Cloud drives sign in through the browser; Google Drive can use your own OAuth client ID, with setup steps in the dialog
- Passwords are kept in the desktop keyring, never in the settings file
- **Tray icon** with a mount/unmount toggle per server; closing the window keeps the app running
- **Mount at login** per server, and **Start at Login** for the app, which starts hidden in the tray
- **Import from `~/.ssh/config`**: hosts are mounted by alias, so your keys, users and ports apply
- Google Drive shows how many files are still waiting to upload, and warns before unmounting while some are
- Desktop notifications for lost connections, finished uploads and failed mounts while the window is hidden
- Menu bar for desktop global menus (Ctrl+N, Ctrl+Q)
- English and 繁體中文, following the system language or chosen in the menu
- About page with the contributor list

## Installing

Download `hamasen_1.0.0_all.deb` and install it:

```bash
sudo apt install ./hamasen_1.0.0_all.deb
```

## Known limitations

- Servers are live mounts. There is no local copy, no per-file sync badge and no right-click actions in the file manager
- SSH keys are applied through `~/.ssh/config` or ssh-agent; there is no key picker in the dialog
- Google Drive uses rclone's shared client ID unless you enter your own; Google is retiring the shared one during 2026
- SFTP, SMB and Google Drive have been used on Ubuntu 26.10 (GNOME 51). FTP, WebDAV, NFS, OneDrive, Dropbox and S3 are implemented but have not yet been tried against real servers
- The first connection to a slow SFTP, FTP or SMB server can take a while
- Simplified Chinese shows English
- The package is architecture-independent but has only been tested on x86-64
